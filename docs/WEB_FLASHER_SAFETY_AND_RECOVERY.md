# Web flasher safety, backup and recovery requirements

## Scope
GitHub Pages + Web Serial on supported Chromium browsers over HTTPS. No Windows desktop installer in the initial release. Browser support and serial permissions vary by OS/browser. Web Serial access alone does not imply flash readback or device compatibility.

## User journey (future, not currently enabled)
1. Read risk notice and recovery guide; acknowledge possible unbootable device and data loss.
2. Choose USB serial port explicitly; verify chip, flash capacity, board revision and compatible image.
3. Attempt complete flash readback, including factory firmware on new boards, using a tested ROM-loader protocol implementation. Do not confuse a download of project firmware with a backup of the user's device.
4. Save backup locally with board metadata, size, timestamp and SHA-256; warn that backup can contain Wi-Fi credentials, API keys and password material. Never upload it to GitHub or a server.
5. Confirm local save and integrity; where practical perform independent readback verification. Browser downloads alone do not prove a file was durably stored.
6. Block flashing if backup cannot be verified. Any future override must be a separately reviewed safety decision, not a hidden default.
7. Show exact image version, source SHA, offsets, target flash size, and erase/preserve behavior. Require a second explicit confirmation.
8. Flash and verify, then test boot and first-run setup. Offer recovery instructions on failure.

## Release gates
- Provenance: release images generated by a reproducible CI job and tied to exact commit and SHA-256 manifest.
- Compatibility: chip, flash size, board revision, partition map and image offsets checked; no guessed values.
- Backup: real browser full-read support, verified file size and hash, user-controlled save and documented restore tested on hardware.
- Recovery: verified ROM entry, backup restore and factory recovery tested on supported hardware.
- Security: explicit user consent, no auto-connect, no upload of private flash contents, safe CSP, dependency/license review.
- Testing: interrupted reads/writes, unplugged USB, insufficient storage, unsupported board, denied permissions, encrypted flash and corrupt images.

## Risk text for the installer
**Firmware flashing can make your device unbootable and may permanently erase factory software and saved settings. Recovery is often possible through ESP32 ROM download mode, but is not guaranteed.** Read the [recovery guide](../installer-web/recovery/) before proceeding.

**Full backups are sensitive.** They may contain Wi-Fi credentials, YouTube API keys, administrator authentication material and other secrets. Keep them private, preferably encrypted, and never commit them to a public repository.

## Current status
Documentation and read-only diagnostics only. No live browser backup, write, erase or restore functions are enabled. This document defines acceptance criteria, not completed functionality.
